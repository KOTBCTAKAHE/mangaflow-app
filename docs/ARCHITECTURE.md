# Архитектура приложения

## Слои
| Слой | Где | Правило |
|---|---|---|
| Presentation | `features/*`, `widgets/*` | только отображение и события; состояние в Riverpod-провайдерах и контроллерах |
| Controllers | `ReaderController`, `MangaSearchController`, `SettingsController`, `AuthController` | логика экрана, без виджетов |
| Repositories | `data/repositories/*` | единая точка доступа к данным, offline-фолбэк, пометка «dirty» |
| Services | `data/services/*` | загрузки, синхронизация, бэкапы, уведомления, фон |
| Data sources | `data/remote/*` (Dio), `data/local/*` (sqflite) | |

Зависимости собираются в `core/providers.dart`. Каждая мутация локальных данных увеличивает `dataVersionProvider`, на который подписаны списки, и ставит синхронизацию в очередь с debounce 3 с.

## Offline-first
1. Всё, что видит и меняет пользователь, сначала пишется в SQLite (`core/storage/database.dart`).
2. Тайтлы, открытые хотя бы раз, кэшируются в `title_cache`, поэтому без сети доступны страница тайтла и список глав.
3. Скачанные главы лежат в `Documents/downloads/<source>/<hash>/0000.webp…` и читаются с диска без обращения к серверу.
4. `SyncEngine` (только если пользователь вошёл): push настроек, библиотеки, прогресса и истории → pull по `since` → коллекции → лента обновлений. Запускается при старте, раз в 5 минут, при появлении сети, при сворачивании и разворачивании приложения и после локальных изменений.

## Читалка
- `ReaderController` хранит загруженные главы (`segments`), текущую позицию, режим и сессию чтения: активное время по секундомеру, который останавливается в фоне, и просмотренные страницы.
- `VerticalReader` — `CustomScrollView` с `center`-якорем. Он умеет начинать с любой страницы, не зная высоты картинок, и подгружает следующую главу, когда виден конец текущей. Видимая страница определяется по положению отрисованных элементов, проверка не чаще раза в 120 мс.
- `PagedReader` — `PageView` (`reverse` для RTL), развороты в режиме «две страницы», `InteractiveViewer` с анимированным двойным тапом. Пока страница увеличена, листание заблокировано.
- Память: изображения декодируются под ширину экрана (`ResizeImage`), глобальный кэш ограничен 120 МБ / 200 изображениями, `cacheExtent` — 2,5 экрана.
- Прогресс сохраняется с debounce 400 мс, сразу при сворачивании и при выходе. Сессия истории тоже записывается при сворачивании, на случай если систему убьёт процесс.

## Загрузки
`DownloadManager` держит очередь в SQLite. Одновременно скачивается одна глава, страницы — по 3 параллельно, с повторами. Сначала файл пишется как `*.part`, потом атомарно переименовывается. При старте приложения и при смене сети загрузки возобновляются, есть режим «только Wi-Fi». Готовые главы отправляются в реестр устройств на сервере.

## Уведомления
WorkManager раз в 6 часов: для пользователя с аккаунтом забирает серверную ленту `/updates`, для гостя сравнивает список глав тайтлов из библиотеки с локальным кэшем. Новые главы показываются через `flutter_local_notifications` и помечаются бейджами в библиотеке.
